# ROADMAP — требования к дальнейшей разработке SIND-site

> Читать после Instruction.md и SNAP_1…4. Это список работ с приоритетами.
> ИИ: перед началом любой задачи — сначала предложить план и список затрагиваемых файлов, дождаться «ок», потом код.

## 0. Правила выполнения задач

1. **Одна задача = один коммит.** Не смешивать задачи.
2. Не более **3–4 файлов** за один шаг. Больше — разбить на подшаги.
3. Код выдавать **файлом целиком** с полным путём (`src/app/...`). Кусками — только если файл > 300 строк, тогда чётко: «заменить блок от … до …».
4. Перед изменением `src/db/schema.ts` — предупредить, что потребуется `npx drizzle-kit push`, и описать миграцию.
5. Новые переменные окружения → одновременно в `.env.example`, `render.yaml` (`sync: false`) и напоминание добавить в Render → Environment.
6. Не менять `package.json` без необходимости. Новые пакеты — только с обоснованием и командой `npm install <pkg>`.
7. После каждой задачи — «Проверка»: какие команды выполнить и что должно быть видно в браузере.
8. Первый шаг в новом чате — **ревизия без правок**: пройти по списку A и написать, что из этого уже сделано в коде, что нет, что требует уточнения.

**Definition of Done для любой задачи:**
- `npm run typecheck` и `npm run build` проходят
- проверено локально в браузере
- проверено на Render после деплоя (если задача влияет на прод)
- закоммичено с префиксом задачи: `[A1] ...`
- если задача меняет процесс — обновлены README.md / Instruction.md

## Приоритет A — стабильность и безопасность (делать первыми, по порядку)

### A1. Авторизация под HTTPS на Render
Проверить `src/app/api/auth/login/route.ts`, `logout/route.ts`, `me/route.ts`, `src/proxy.ts`:
- cookie сессии: `httpOnly: true`, `sameSite: "lax"`, `secure: process.env.NODE_ENV === "production"`, `path: "/"`
- срок жизни сессии задаётся в одном месте (константа), сейчас заявлено 30 минут
- при невалидной/просроченной сессии — редирект на страницу входа, а не пустая страница
- `ACCESS_TOKEN` сравнивается безопасно (не утекает в логи и ответы)
Проверка: логин на `sandalis-web-mtbf.onrender.com`, обновление страницы, переход по разделам — сессия держится.

### A2. `/api/health` с проверкой базы
`src/app/api/health/route.ts` должен делать `SELECT 1` через пул и возвращать `200 {ok:true, db:"up"}` либо `503 {ok:false, db:"down", error}`. Нужен для health-check Render и для пинга, который не даст Supabase уйти на паузу. Не должен требовать авторизации (проверить исключение в `proxy.ts`).

### A3. Фоновое видео на главной
`src/app/page.tsx`:
- `src={process.env.NEXT_PUBLIC_VIDEO_URL ?? "/Videos/Video Project.mp4"}`
- добавить `poster` (кадр из `public/bg/`), `preload="metadata"`, `muted playsInline autoPlay loop`
- на мобильных / при `prefers-reduced-motion` — показывать только постер
- если переменная не задана и файла нет — страница не должна ломаться
Переменная `NEXT_PUBLIC_VIDEO_URL` → `.env.example`, `render.yaml`.

### A4. Понятные ошибки вместо падений
Страницы, зависящие от БД (`orders`, `timers`, `cabinet`, `storage`): при недоступности базы показывать блок «База данных недоступна, попробуйте позже» с кнопкой «Повторить», а не белый экран / 500. API-роуты возвращают JSON с `error` и корректным статусом. Добавить `src/app/error.tsx` и `src/app/not-found.tsx` в стиле сайта, если их нет.

### A5. Чистка зависимостей и репозитория
- Проверить использование `ffmpeg-static` (`Select-String` по `src`, `scripts`). Не используется → `npm uninstall ffmpeg-static`.
- Проверить `xlsx` — используется в `exporters.ts`? Если да, оставить.
- `all_files_paths.txt` → удалить из репо, добавить в `.gitignore`.
- `public/3d-models` — проверить размер; > 30 МБ суммарно → вынести во внешнее хранилище.
- `npm run lint` — довести до нуля ошибок (предупреждения допустимы).

### A6. Ничего не писать на диск сервера
Проверить `scripts/`, `src/app/api/scan`, `src/app/api/storage`, экспортёры: файловая система Render эфемерна. Любая запись файлов → в БД или в ответ клиенту (download). Если такого нет — отметить «проверено, ок».

### A7. Логи
Убедиться, что в консоль не попадают `DATABASE_URL`, токены, тела запросов с секретами. Единый префикс для серверных логов (`[SIND]`), ошибки БД — уже есть `[DB_POOL_ERROR]`.

## Приоритет B — функционал (по одному, после согласования дизайна таблиц)

### B1. Участники и роли
Таблица `members`: `id`, `discordId`, `displayName`, `role` (`officer` | `logistics` | `member`), `tokenHash`, `isActive`, `createdAt`, `lastSeenAt`.
- вход по персональному токену; общий `ACCESS_TOKEN` остаётся как мастер-ключ офицера
- `proxy.ts` и API проверяют роль: создавать/удалять заказы и склады — `logistics` и выше; управлять участниками — только `officer`
- страница управления участниками в разделе Кабинет (только офицер)
- миграция: существующий `ACCESS_TOKENS_JSON` импортируется в таблицу скриптом `scripts/import-members.mjs`

### B2. Журнал действий
Таблица `audit_log`: `id`, `at`, `memberId`, `action`, `entity` (`order` | `stockpile` | `member` | `announcement`), `entityId`, `payload` (jsonb).
- пишется из всех мутирующих API-роутов
- вкладка «Журнал» в Кабинете: фильтр по типу, по участнику, последние 200 записей

### B3. Объявления и бегущая строка из БД
Таблица `announcements`: `id`, `text`, `kind` (`ticker` | `banner`), `isActive`, `priority`, `startsAt`, `endsAt`, `createdBy`.
- `Ticker.tsx` читает активные записи вместо захардкоженного текста
- редактирование в Кабинете (роль `officer`)

### B4. Комментарии к заказам и складам
Таблица `comments`: `id`, `entity`, `entityId`, `memberId`, `text`, `createdAt`. Лента комментариев в карточке заказа и склада.

### B5. Прогресс тренировок
Таблица `training_progress`: `memberId`, `moduleId`, `completedAt`. Отметки «пройдено» на странице Training, сводка по участникам для офицера.

### B6. Статистика по войнам
Поле `warNumber` у заказов (или таблица `wars`). Страница сводки: произведено по категориям за войну, сравнение войн.

### B7. Личные настройки в БД
Тема, избранные предметы, последняя вкладка — из `localStorage` в таблицу `member_settings` (jsonb), синхронизация между устройствами.

## Приоритет C — эксплуатация

### C1. Скрипт экспорта базы
`scripts/db-export.mjs`: выгружает все таблицы в `backups/db-YYYYMMDD.json` (папка в `.gitignore`). Команда `npm run db:export`. Обратный `db-import.mjs` — по желанию.

### C2. Команды в package.json
Добавить: `"db:push": "drizzle-kit push"`, `"db:studio": "drizzle-kit studio"`, `"db:export": "node scripts/db-export.mjs"`.

### C3. Документация
При каждом изменении процесса или переменных — обновлять README.md (разделы 8, 9, 11, 15) и Instruction.md. ИИ должен явно писать: «обновите в README раздел N: …».

## Не делать без явного запроса владельца

- Не менять стек (Next.js 16, Drizzle, Tailwind 4, `pg`-драйвер).
- Не переносить каталог предметов / коды / рецепты из `src/lib/*.ts` в БД (они меняются раз в патч, в коде удобнее).
- Не добавлять UI-библиотеки (shadcn, MUI и т.п.) — есть свои компоненты в `src/components/ui`.
- Не внедрять внешние сервисы (Discord OAuth, аналитика), пока не согласовано.
- Не удалять и не переименовывать существующие API-роуты — на них может опираться клиентский код.
