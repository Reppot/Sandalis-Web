## 2. Что это вообще такое (карта проекта)

**SIND-site** — сайт клана для игры Foxhole: заказы на производство, склады, таймеры, база кодов предметов, карта, тренировки.

Проект состоит из трёх частей, которые живут в разных местах:

```
┌─────────────────────────────┐
│  ВАШ КОМПЬЮТЕР              │   D:\Sandalis Web\SIND-site
│  Здесь вы редактируете код  │   Запуск: npm run dev → localhost:3000
└──────────────┬──────────────┘
               │ git push
               ▼
┌─────────────────────────────┐
│  GITHUB                     │   github.com/Reppot/Sandalis-Web
│  Хранилище кода и история   │   Каждый коммит = точка восстановления
└──────────────┬──────────────┘
               │ автоматически при каждом push
               ▼
┌─────────────────────────────┐        ┌────────────────────────────┐
│  RENDER (хостинг)           │ ─────► │  SUPABASE (база данных)    │
│  Сайт в интернете           │        │  Заказы, склады, таймеры   │
│  sandalis-web-mtbf          │        │  PostgreSQL                │
│  .onrender.com              │        │                            │
└─────────────────────────────┘        └────────────────────────────┘
```

**Как это работает вместе:**
- Вы меняете код на компьютере → проверяете локально → отправляете на GitHub (`git push`).
- Render видит новый код на GitHub и **сам** пересобирает и перезапускает сайт (3–5 минут).
- И локальный сайт, и сайт на Render ходят в **одну и ту же** базу Supabase. То есть заказ, созданный на localhost, появится и на «боевом» сайте.

**Технологии** (знать названия достаточно, чтобы говорить с ИИ):
- **Next.js 16** — фреймворк сайта (движок). Версия 16.2.6.
- **React 19** — библиотека интерфейса.
- **TypeScript** — язык (JavaScript с типами).
- **Tailwind CSS 4** — стили.
- **Drizzle ORM** — прослойка между кодом и базой данных.
- **PostgreSQL** — сама база данных (у Supabase).

**Файлы в папке проекта — что зачем:**

| Путь | Что это | Трогать? |
|---|---|---|
| `src/app/*/page.tsx` | страницы сайта (одна папка = один раздел) | через ИИ |
| `src/app/api/**/route.ts` | серверные обработчики (API) | через ИИ |
| `src/components/` | кусочки интерфейса по разделам | через ИИ |
| `src/lib/` | данные и логика (каталог предметов, коды, карта) | через ИИ |
| `src/db/schema.ts` | описание таблиц базы данных | через ИИ, осторожно |
| `src/proxy.ts` | проверка авторизации на каждом запросе | через ИИ |
| `public/` | картинки, иконки, фоны — отдаются как есть | можно руками |
| `public/FoxholeWikiPhotos/` | 378 иконок предметов | можно добавлять |
| `.env` | **секреты**: пароль базы, пароль сайта | руками, осторожно |
| `.env.example` | шаблон `.env` без секретов | — |
| `package.json` | список зависимостей и команд | **не трогать без нужды** |
| `package-lock.json` | точные версии зависимостей | **не трогать руками** |
| `node_modules/` | установленные библиотеки (огромная папка) | **не трогать**, не в git |
| `.next/` | сборочный мусор | **не трогать**, не в git |
| `render.yaml` | настройки хостинга Render | редко |
| `drizzle.config.ts` | настройки подключения к базе | редко |
| `Instruction.md` | правила для ИИ | читать ИИ |
| `SNAP_1…4.md` | автоснимки кода для ИИ | не редактировать, генерируются сами |
| `scripts/snapshot.ps1` | генератор снимков | — |
| `README.md` | этот файл | — |

## 3. Словарь терминов

| Термин | Простыми словами |
|---|---|
| **Терминал / PowerShell** | Чёрное окно, куда пишут команды текстом. |
| **Команда** | Строка текста, которую вы вводите в терминал и нажимаете Enter. |
| **Git** | Программа-«машина времени» для кода. Запоминает каждое сохранение, позволяет откатиться. |
| **Коммит (commit)** | Одно «сохранение» в git с подписью, что сделано. Точка, к которой можно вернуться. |
| **Пуш (push)** | Отправить коммиты с компьютера на GitHub. |
| **Пул (pull)** | Скачать коммиты с GitHub на компьютер. Опасная операция, см. 6.5. |
| **Репозиторий (репо)** | Папка проекта под управлением git + её копия на GitHub. |
| **Ветка (branch)** | Параллельная версия кода. У нас рабочая — `main`. Ветка `vite-rewrite` — мусор. |
| **Хеш коммита** | Код вида `d2e8b7d` — «номер» сохранения. |
| **npm** | Менеджер библиотек. `npm run dev` — запустить сайт, `npm install` — установить библиотеки. |
| **node_modules** | Папка, куда npm складывает библиотеки. Её можно удалить и восстановить командой `npm install` — **но только если `package.json` правильный**. |
| **Сборка (build)** | Превращение исходного кода в готовый сайт. Делает `npm run build` и Render. |
| **Деплой (deploy)** | Выкладка новой версии сайта на хостинг. Render делает сам после `git push`. |
| **Хостинг** | Сервер в интернете, где крутится сайт. У нас Render. |
| **База данных (БД)** | Место, где хранятся заказы, склады и т.д. У нас Supabase (PostgreSQL). |
| **Переменные окружения (env)** | Настройки-секреты, которые не пишут в код: пароль базы, пароль сайта. Лежат в `.env` локально и в панели Render. |
| **DATABASE_URL** | Строка подключения к базе — адрес + логин + пароль в одной строке. |
| **ACCESS_TOKEN** | Пароль для входа на сайт (клановый). |
| **localhost:3000** | Адрес сайта, запущенного на вашем компьютере. Виден только вам. |
| **Снимок (SNAP)** | Файлы `SNAP_1…4.md` — весь код проекта, собранный в текст, чтобы вставить ИИ в чат. |

## 4. Как открыть терминал и выполнять команды

**Способ 1 (проще всего):** откройте папку `D:\Sandalis Web\SIND-site` в Проводнике → кликните правой кнопкой по пустому месту → **«Открыть в Терминале»** (или «Open in Terminal» / «PowerShell здесь»).

**Способ 2:** Пуск → напишите `PowerShell` → Enter → в открывшемся окне:
```powershell
cd "D:\Sandalis Web\SIND-site"
```
(кавычки обязательны — в пути есть пробел).

**Правила работы с терминалом:**
- Каждую команду вводите и нажимайте **Enter**.
- Если команда «зависла» и что-то показывает (например, `npm run dev`) — она работает. Остановить: **Ctrl+C**.
- Копировать из терминала: выделить мышью → **Ctrl+C** (или Enter). Вставить: **Ctrl+V** или правая кнопка мыши.
- Если в терминале русские буквы показаны кракозябрами (`РџСЂРё`) — это только отображение, сами файлы нормальные.
- Красный текст — не всегда ошибка. Ошибка — когда команда завершилась и написала `error`, `failed`, `Cannot find`.
- Предупреждения `warning: LF will be replaced by CRLF` — безвредны, игнорируйте.
- `npm warn`, `vulnerabilities`, `deprecated`, `looking for funding` — шум, игнорируйте. **Никогда** не выполняйте `npm audit fix --force`.

**Как показать вывод ИИ:** выделите текст в терминале, скопируйте, вставьте в чат. Если вывод длинный — последние 30–40 строк обычно достаточно.

## 6. Git — сохранение и откат изменений

### 6.1 Золотое правило

> **Перед любыми правками — `git status` должен быть чистым.**
> **После каждого рабочего результата — коммит и пуш.**

Тогда любая неудачная правка откатывается за секунду, а не восстановлением из бэкапа.

### 6.2 Посмотреть состояние

```powershell
git status
```
- `nothing to commit, working tree clean` — всё сохранено, можно работать.
- `modified: ...` — файлы изменены, но не сохранены в git.
- `Untitled files: ...` / `Untracked files:` — новые файлы, git о них ещё не знает.
- `Your branch is behind 'origin/main'` — на GitHub есть коммиты, которых нет у вас. **Не спешите делать pull**, см. 6.5.

### 6.3 Сохранить изменения (коммит + пуш)

```powershell
git add -A
git commit -m "Что сделано, коротко по-русски"
git push
```
Пример подписи: `"Добавлен фильтр на страницу заказов"`.
После `git push` Render автоматически начнёт пересборку сайта (раздел 8).

### 6.4 Откатить изменения

**Откатить всё незакоммиченное** (вернуться к последнему коммиту):
```powershell
git checkout .
```

**Откатить один файл:**
```powershell
git checkout -- src/app/page.tsx
```

**Посмотреть историю:**
```powershell
git log --oneline -15
```
Покажет список вида `8e6576c Sync lockfile`. Левая колонка — хеш.

**Откатиться на конкретный коммит** (все правки после него потеряются):
```powershell
git reset --hard 8e6576c
npm run dev                    # проверить, что работает
git push --force-with-lease origin main    # перезаписать GitHub
```
Render передеплоит откаченную версию.

**Посмотреть, что изменилось в файле:**
```powershell
git diff src/app/page.tsx
```

### 6.5 Безопасный pull (скачать с GitHub)

Нужно только если работали с другого компьютера или кто-то ещё менял репозиторий. **Никогда не делайте `git pull` вслепую** — именно так в проект однажды приехала сломанная версия.

```powershell
git fetch
git log --oneline main..origin/main              # какие коммиты прилетят
git show --stat origin/main | Select -First 40   # какие файлы изменятся
```
Если в списке файлов есть `package.json`, `vite.config.ts`, `index.html`, `src/App.tsx`, `src/main.tsx` — **стоп, не тянуть**. Иначе:
```powershell
git pull
```

### 6.6 Ветки

Рабочая ветка — **`main`**. Только с ней и работаем.
Ветка `vite-rewrite` — архив ошибочной переделки. Удалить (когда захочется):
```powershell
git push origin --delete vite-rewrite
git branch -D vite-rewrite
```

### 6.7 Что git НЕ хранит

Файлы из `.gitignore` не попадают в репозиторий: `node_modules`, `.next`, `.env`, `*.mp4`, `SNAP_*.md`, `Instruction.md`. Это значит: если клонировать репо на другой компьютер, их там не будет — раздел 14.

## 7. Работа с ИИ (нейросетью)

### 7.1 Главное, что нужно понимать

- ИИ **не помнит** предыдущие чаты. Каждый новый чат — с нуля.
- ИИ **не видит** ваши файлы и не может их менять. Он видит только то, что вы вставили в чат, и отдаёт код текстом.
- ИИ без контекста склонен «пересоздать проект заново» — так однажды сайт чуть не переписали на другой движок. Защита от этого — файлы `Instruction.md` и `SNAP_*.md`.

### 7.2 Начало нового чата — пошагово

**Подготовка (в терминале):**
```powershell
cd "D:\Sandalis Web\SIND-site"
git status                                   # должно быть чисто
Get-Content SNAP_1_core.md -TotalCount 1     # хеш в первой строке
git log --oneline -1                         # должен совпадать
```
Если хеши не совпадают — `npm run snapshot`.

**В чате — 6 сообщений подряд:**

| № | Открыть файл, скопировать всё, вставить | Подпись под вставкой |
|---|---|---|
| 1 | `Instruction.md` | «Это правила проекта. Прочитай. Пока не отвечай, жди код.» |
| 2 | `SNAP_1_core.md` | «Снимок кода, часть 1 из 4. Пока не отвечай.» |
| 3 | `SNAP_2_app.md` | «Часть 2 из 4. Пока не отвечай.» |
| 4 | `SNAP_3_shell.md` | «Часть 3 из 4. Пока не отвечай.» |
| 5 | `SNAP_4_workspaces.md` | «Часть 4 из 4. Пока не отвечай.» |
| 6 | — | «Это всё. Задача: …» |

Файлы открывать Блокнотом или VS Code, `Ctrl+A`, `Ctrl+C`.

Если ИИ попросит показать `factory-data.ts`, `item-catalog.ts`, `itemCodes.ts` или `globals.css` целиком — в снимках они обрезаны (большие). Откройте файл из `src/lib/` или `src/app/` и вставьте отдельно.

### 7.3 Как применять код от ИИ

```
1. git status                        → чисто
2. ИИ указал путь файла              → открыть этот файл, заменить содержимое (или вставить кусок, как указано)
3. npm run dev                       → проверить в браузере
4a. Работает   → git add -A ; git commit -m "..." ; git push
4b. Сломалось  → git checkout .      → написать ИИ: «ошибка: <текст из терминала/браузера>»
```

Просите ИИ давать **файл целиком** и **полный путь** — так меньше ошибок при вставке. Если ИИ меняет больше 3–4 файлов за раз — попросите разбить на шаги.

### 7.4 Красные флаги — когда остановиться и переспросить

ИИ предлагает:
- перейти на Vite / создать `vite.config.ts` / `index.html` / `src/App.tsx` / `src/main.tsx`
- «создать `package.json`» или переписать его целиком
- `npm install` для «восстановления проекта»
- «начнём с чистого проекта»
- удалить `src/app` или `src/components`

Ответ ИИ в таких случаях: **«Нет. Проект уже существует на Next.js 16, читай Instruction.md. Работаем внутри существующей структуры.»** Если ИИ упорствует — новый чат.

### 7.5 Когда чат «поплыл»

Признаки: забывает структуру, предлагает файлы, которых нет, повторяет ошибки, отвечает всё медленнее. Не спорьте — откройте новый чат по 7.2. Снимки актуальны на последний коммит, так что ничего не потеряется.

### 7.6 Снимки обновляются сами

После каждого `git commit` срабатывает хук, который пересобирает `SNAP_*.md`. Проверить:
```powershell
Get-Item SNAP_*.md | Select Name, LastWriteTime
```
Время должно совпадать с последним коммитом. Если нет — раздел 12.7.

Вручную: `npm run snapshot`.

## 8. Хостинг Render — сайт в интернете

### 8.1 Адреса

- **Сайт:** https://sandalis-web-mtbf.onrender.com
- **Панель управления:** https://dashboard.render.com → сервис `sandalis-web-mtbf`
- **Blueprint** (настройки из `render.yaml`): в панели → Blueprints → `sandalis-web`

### 8.2 Как происходит выкладка

Вы делаете `git push` в ветку `main` → Render в течение минуты замечает → скачивает код → `npm ci --include=dev && npm run build` (2–4 мин) → `npm run start` → сайт обновлён. Вам ничего делать не нужно.

Следить за процессом: панель → сервис → **Events** (список деплоев) и **Logs** (живой лог).

Успешный лог заканчивается на:
```
▲ Next.js 16.2.6
✓ Ready
==> Your service is live 🎉
```

### 8.3 Бесплатный тариф — что нужно знать

| Особенность | Что это значит для вас |
|---|---|
| **Засыпает через 15 минут** без посетителей | Первый заход после простоя — 30–60 секунд белого экрана. Дальше быстро. Это нормально. |
| 750 часов в месяц | Хватает на один сервис круглосуточно. |
| 512 МБ памяти | Если сборка упадёт с `heap out of memory` — раздел 12.5. |
| Диск не сохраняется | Файлы на сервер писать нельзя — только в базу или внешнее хранилище. |
| 100 ГБ трафика в месяц | Для клана — с запасом, если не раздавать тяжёлое видео с Render. |

Чтобы сайт не засыпал: бесплатный сервис **cron-job.org** → создать задание → URL `https://sandalis-web-mtbf.onrender.com/api/health` → каждые 10 минут. Либо платный тариф Starter ($7/мес) — сервис не спит и памяти больше.

### 8.4 Переменные окружения на Render

Панель → сервис → **Environment**. Там лежат:
- `DATABASE_URL` — подключение к Supabase
- `ACCESS_TOKEN` — пароль сайта
- `ACCESS_TOKENS_JSON` — дополнительные токены (может быть `[]`)
- `NEXT_PUBLIC_VIDEO_URL` — ссылка на видео (если настроено)
- `NODE_VERSION=22`, `NODE_ENV=production` — технические

После изменения любой переменной → **Save Changes** → Render сам передеплоит.

**Важно:** переменные с префиксом `NEXT_PUBLIC_` вшиваются в сайт при сборке. Меняете такую — обязательно дождитесь передеплоя (или запустите Manual Deploy).

### 8.5 Ручной передеплой

Панель → сервис → кнопка **Manual Deploy** → **Deploy latest commit**. Нужно редко: когда поменяли переменную окружения и хотите ускорить, или когда Render «не заметил» push.

Если после правки `render.yaml` Render не применил новые настройки: Blueprints → `sandalis-web` → **Manual sync**.

### 8.6 Посмотреть логи работающего сайта

Панель → сервис → **Logs**. Здесь видны ошибки, которые случаются у посетителей (например, `[DB_POOL_ERROR]` — проблемы с базой).

### 8.7 Файл render.yaml

Лежит в корне проекта, описывает сервис. Менять редко. Сейчас там: имя `sandalis-web`, регион Франкфурт, бесплатный тариф, ветка `main`, команды сборки и запуска, health-check `/api/health`, список переменных. ## 9. База данных Supabase

### 9.1 Адреса

- **Панель:** https://supabase.com/dashboard → проект (ref `imoeicmsrtvsigjglqqy`)

Таблицы описаны в `src/db/schema.ts`. Это заказы, склады (stockpiles), профили и т.д. — всё, что пользователи создают на сайте. Картинки и код там **не** хранятся.

Локальный сайт (localhost) и Render используют **одну и ту же** базу. Тестовые заказы, созданные локально, будут видны всем. Если нужна отдельная тестовая база — попросите ИИ помочь создать второй проект Supabase и второй `DATABASE_URL` в `.env`.

### 9.4 Изменение структуры базы

Когда ИИ меняет `src/db/schema.ts` (добавляет таблицу или столбец), это надо применить к базе:
```powershell
npx drizzle-kit push
```
Команда покажет, что собирается сделать, и спросит подтверждение. Делать **до** пуша на GitHub, иначе Render запустит новый код на старой базе и страницы упадут.

Графический интерфейс базы прямо с компьютера:
```powershell
npx drizzle-kit studio
```
Откроется в браузере.

### 9.5 Бесплатный тариф Supabase

| Особенность | Что делать |

## 10. Видео и большие файлы

### 10.1 Ограничения

- GitHub: **100 МБ на файл** — иначе `git push` отклоняется.
- Supabase Storage (Free): **50 МБ на файл**.
- Render Free: раздача тяжёлых файлов съедает трафик и тормозит.
- Фоновое видео на главной — исходник `public/Videos/Video Project.mp4`, **225 МБ**. В git его нет (`*.mp4` в `.gitignore`), поэтому на Render его нет.

### 10.2 Текущее состояние

Главная страница (`src/app/page.tsx`) берёт видео из переменной `NEXT_PUBLIC_VIDEO_URL`, а если её нет — из `/Videos/Video Project.mp4` (работает только локально).

_(Впишите сюда, что выбрали, когда решите: «видео лежит на Backblaze B2 по адресу …» или «сжато до … МБ и лежит в Supabase Storage bucket `media`».)_

### 10.3 Вариант без сжатия — Backblaze B2 (бесплатно 10 ГБ)

1. https://www.backblaze.com → B2 Cloud Storage → регистрация.
2. Buckets → Create → **Public** → создать.
3. Upload → загрузить файл, переименованный в `video.mp4` (без пробелов).
4. Кликнуть файл → скопировать **Friendly URL**.
5. Вписать URL в `.env` как `NEXT_PUBLIC_VIDEO_URL=...` и в Render → Environment.
6. `git push` (или Manual Deploy).

### 10.4 Вариант со сжатием — Supabase Storage

Сжать (визуально без потерь; `ffmpeg` уже есть в проекте):
```powershell
cd "D:\Sandalis Web\SIND-site"
& "node_modules\ffmpeg-static\ffmpeg.exe" -i "public\Videos\Video Project.mp4" -c:v libx264 -crf 18 -preset slow -an -movflags +faststart "public\Videos\video.mp4"
[math]::Round((Get-Item "public\Videos\video.mp4").Length / 1MB)
```
Если больше 45 МБ — заменить `-crf 18` на `-crf 22`. Затем: Supabase → Storage → New bucket `media` (**Public**) → Upload → Copy URL → в `.env` и Render как в 10.3.

### 10.5 Другие большие файлы

Любой файл больше ~10 МБ: не в git, а во внешнее хранилище + ссылка. Если случайно закоммитили и `git push` ругается `larger than 100 MB`:
```powershell
git rm --cached "путь/к/файлу"
Add-Content .gitignore "`nпуть/к/файлу"
git commit --amend --no-edit
git push
```

## 11. Секреты, пароли и файл .env

### 11.1 Что где

Файл **`.env`** в корне проекта — только на вашем компьютере, в git не попадает. Содержит:
```
DATABASE_URL="postgresql://postgres.<ref>:<пароль>@aws-1-eu-west-1.pooler.supabase.com:6543/postgres?pgbouncer=true"
ACCESS_TOKEN="<пароль входа на сайт>"
NEXT_PUBLIC_VIDEO_URL=<ссылка на видео>
```
Те же значения лежат в **Render → сервис → Environment** (без кавычек).

Файл **`.env.example`** — шаблон без секретов, он в git. Если добавляете новую переменную в `.env` — добавьте её и в `.env.example` с заглушкой.

### 11.2 Правила

- **Никогда** не вставляйте `.env` целиком в чат с ИИ. Показывайте с заменой значений на `***`:
  ```powershell
  (Get-Content .env) -replace '=.*', '=***'
  ```
- **Никогда** не коммитьте `.env`. Проверка: `git ls-files .env` должно быть пусто.
- Если секрет засветился (в чате, скриншоте, где угодно) — **сменить**:
  - Пароль базы: Supabase → Project Settings → Database → Reset database password. Новый пароль — только латинские буквы и цифры, 20+ символов (спецсимволы вроде `!@#%` ломают строку подключения). Обновить `DATABASE_URL` в `.env` и в Render.
  - `ACCESS_TOKEN`: придумать длинный, обновить в `.env` и в Render. Сообщить клану.
- `ACCESS_TOKEN` вида `0000` подбирается за секунду. Ставьте нормальный.

### 11.3 Где взять DATABASE_URL заново

Supabase → Project Settings → Database → **Connection string** → вкладка **Transaction pooler** → скопировать → заменить `[YOUR-PASSWORD]` на реальный пароль → в конец добавить `?pgbouncer=true`.

## 12. Что-то сломалось — диагностика по симптомам

### 12.1 `npm run dev` пишет `vite` или `"vite" не является командой`

Подменён `package.json`. **Не запускайте `npm install`.**
```powershell
Select-String package.json -Pattern '"next"'      # пусто = подменён
git checkout -- package.json package-lock.json tsconfig.json
Select-String package.json -Pattern '"next"'      # должно найти "next": "16.2.6"
npm run dev
```
Если и после этого пусто — в git тоже сломано: `git log --oneline -- package.json`, найти коммит до поломки, `git checkout <хеш> -- package.json package-lock.json tsconfig.json`.

### 12.2 `Cannot find module` / нет папки `node_modules` / Next не найден

Сначала убедиться, что `package.json` правильный (12.1). Затем:
```powershell
Remove-Item -Recurse -Force node_modules -ErrorAction SilentlyContinue
npm ci
npm run dev
```
`npm ci` ставит точно по `package-lock.json`, 1–2 минуты.

### 12.3 Сайт запускается, но страницы «Заказы»/«Таймеры»/«Кабинет» падают

Проблема с базой. Смотрите в терминале строки `[DB_POOL_ERROR]`, `ECONNREFUSED`, `password authentication failed`, `Tenant or user not found`.
- Проверьте интернет.
- Проверьте, не на паузе ли проект Supabase (панель → Restore).
- Проверьте `DATABASE_URL` в `.env` (раздел 11.3). Если недавно меняли пароль базы — обновили ли строку.
- `DATABASE_URL still contains a placeholder` — в строке остались `<project-ref>` или `<password>`, заменить на реальные.

### 12.4 Локально работает, на Render — нет

Панель Render → сервис → **Logs**. Ищите первую строку с `Error`. Частые:
- `npm ci can only install packages when your package.json and package-lock.json are in sync` → на компьютере: `npm install`, затем `git add package-lock.json; git commit -m "Sync lockfile"; git push`.
- `Cannot find module '@tailwindcss/postcss'` → в `render.yaml` команда сборки должна быть `npm ci --include=dev && npm run build`.
- `DATABASE_URL is required` → переменная не задана в Render → Environment.
- Сборка прошла, но `health check failed` → `/api/health` не отвечает, обычно база (12.3), смотрите логи после `Ready`.

Скопируйте 30–40 строк лога вокруг ошибки — и ИИ.

### 12.5 На Render `JavaScript heap out of memory`

Не хватает 512 МБ на сборку. Render → Environment → добавить `NODE_OPTIONS` = `--max-old-space-size=460` → Save → Manual Deploy. Не помогло → тариф Starter.

### 12.6 Сайт в интернете открывается 40 секунд

Норма для бесплатного Render после 15 минут простоя. Решение — пинг (8.3) или платный тариф.

### 12.7 Снимки SNAP_* не обновляются после коммита

```powershell
Test-Path .git\hooks\post-commit
```
`False` → создать хук:
```powershell
$hook = "#!/bin/sh`npowershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/snapshot.ps1 >/dev/null 2>&1`nexit 0`n"
[IO.File]::WriteAllText("$PWD\.git\hooks\post-commit", $hook)
```
`True`, но не работает → запустить скрипт руками и посмотреть ошибку:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/snapshot.ps1
```
Ошибка с кракозябрами → файл потерял кодировку BOM:
```powershell
$c = Get-Content scripts\snapshot.ps1 -Raw -Encoding UTF8
[IO.File]::WriteAllText("$PWD\scripts\snapshot.ps1", $c, (New-Object System.Text.UTF8Encoding $true))
```

### 12.8 `git push` отклонён: `rejected`, `non-fast-forward`

На GitHub есть коммиты, которых нет у вас. Сначала посмотреть, что там (6.5). Если это ваш же старый мусор и вы уверены — `git push --force-with-lease origin main`.

### 12.9 `git push` отклонён: `file is larger than 100 MB`

Раздел 10.5.

### 12.10 После логина сразу выкидывает / не держит сессию (на Render)

Проблема с cookie под HTTPS. Показать ИИ файлы `src/app/api/auth/login/route.ts` и `src/proxy.ts`.

### 12.11 Не помню, что сломал, всё странно

```powershell
git status          # что изменено
git diff            # что именно
git checkout .      # откатить всё
npm run dev
```
Если и после отката плохо — `git log --oneline -10`, взять хеш последнего заведомо рабочего коммита, `git reset --hard <хеш>`. Совсем плохо — раздел 13.

## 2. Что это вообще такое (карта проекта)

**SIND-site** — сайт клана для игры Foxhole: заказы на производство, склады, таймеры, база кодов предметов, карта, тренировки.

Проект состоит из трёх частей, которые живут в разных местах:

```
┌─────────────────────────────┐
│  ВАШ КОМПЬЮТЕР              │   D:\Sandalis Web\SIND-site
│  Здесь вы редактируете код  │   Запуск: npm run dev → localhost:3000
└──────────────┬──────────────┘
               │ git push
               ▼
┌─────────────────────────────┐
│  GITHUB                     │   github.com/Reppot/Sandalis-Web
│  Хранилище кода и история   │   Каждый коммит = точка восстановления
└──────────────┬──────────────┘
               │ автоматически при каждом push
               ▼
┌─────────────────────────────┐        ┌────────────────────────────┐
│  RENDER (хостинг)           │ ─────► │  SUPABASE (база данных)    │
│  Сайт в интернете           │        │  Заказы, склады, таймеры   │
│  sandalis-web-mtbf          │        │  PostgreSQL                │
│  .onrender.com              │        │                            │
└─────────────────────────────┘        └────────────────────────────┘
```

**Как это работает вместе:**
- Вы меняете код на компьютере → проверяете локально → отправляете на GitHub (`git push`).
- Render видит новый код на GitHub и **сам** пересобирает и перезапускает сайт (3–5 минут).
- И локальный сайт, и сайт на Render ходят в **одну и ту же** базу Supabase. То есть заказ, созданный на localhost, появится и на «боевом» сайте.

**Технологии** (знать названия достаточно, чтобы говорить с ИИ):
- **Next.js 16** — фреймворк сайта (движок). Версия 16.2.6.
- **React 19** — библиотека интерфейса.
- **TypeScript** — язык (JavaScript с типами).
- **Tailwind CSS 4** — стили.
- **Drizzle ORM** — прослойка между кодом и базой данных.
- **PostgreSQL** — сама база данных (у Supabase).

**Файлы в папке проекта — что зачем:**

| Путь | Что это | Трогать? |
|---|---|---|

## 3. Словарь терминов

| Термин | Простыми словами |
|---|---|
| **Терминал / PowerShell** | Чёрное окно, куда пишут команды текстом. |
| **Команда** | Строка текста, которую вы вводите в терминал и нажимаете Enter. |
| **Git** | Программа-«машина времени» для кода. Запоминает каждое сохранение, позволяет откатиться. |
| **Коммит (commit)** | Одно «сохранение» в git с подписью, что сделано. Точка, к которой можно вернуться. |
| **Пуш (push)** | Отправить коммиты с компьютера на GitHub. |
| **Пул (pull)** | Скачать коммиты с GitHub на компьютер. Опасная операция, см. 6.5. |
| **Репозиторий (репо)** | Папка проекта под управлением git + её копия на GitHub. |
| **Ветка (branch)** | Параллельная версия кода. У нас рабочая — `main`. Ветка `vite-rewrite` — мусор. |
| **Хеш коммита** | Код вида `d2e8b7d` — «номер» сохранения. |
| **npm** | Менеджер библиотек. `npm run dev` — запустить сайт, `npm install` — установить библиотеки. |
| **node_modules** | Папка, куда npm складывает библиотеки. Её можно удалить и восстановить командой `npm install` — **но только если `package.json` правильный**. |
| **Сборка (build)** | Превращение исходного кода в готовый сайт. Делает `npm run build` и Render. |
| **Деплой (deploy)** | Выкладка новой версии сайта на хостинг. Render делает сам после `git push`. |
| **Хостинг** | Сервер в интернете, где крутится сайт. У нас Render. |
| **База данных (БД)** | Место, где хранятся заказы, склады и т.д. У нас Supabase (PostgreSQL). |
| **Переменные окружения (env)** | Настройки-секреты, которые не пишут в код: пароль базы, пароль сайта. Лежат в `.env` локально и в панели Render. |
| **DATABASE_URL** | Строка подключения к базе — адрес + логин + пароль в одной строке. |
| **ACCESS_TOKEN** | Пароль для входа на сайт (клановый). |
| **localhost:3000** | Адрес сайта, запущенного на вашем компьютере. Виден только вам. |
| **Снимок (SNAP)** | Файлы `SNAP_1…4.md` — весь код проекта, собранный в текст, чтобы вставить ИИ в чат. |

## 6. Git — сохранение и откат изменений

### 6.1 Золотое правило

> **Перед любыми правками — `git status` должен быть чистым.**
> **После каждого рабочего результата — коммит и пуш.**

Тогда любая неудачная правка откатывается за секунду, а не восстановлением из бэкапа.

### 6.2 Посмотреть состояние

```powershell
git status
```
- `nothing to commit, working tree clean` — всё сохранено, можно работать.
- `modified: ...` — файлы изменены, но не сохранены в git.
- `Untitled files: ...` / `Untracked files:` — новые файлы, git о них ещё не знает.
- `Your branch is behind 'origin/main'` — на GitHub есть коммиты, которых нет у вас. **Не спешите делать pull**, см. 6.5.

### 6.3 Сохранить изменения (коммит + пуш)

```powershell
git add -A
git commit -m "Что сделано, коротко по-русски"
git push
```
Пример подписи: `"Добавлен фильтр на страницу заказов"`.
После `git push` Render автоматически начнёт пересборку сайта (раздел 8).

### 6.4 Откатить изменения

**Откатить всё незакоммиченное** (вернуться к последнему коммиту):
```powershell
git checkout .
```

**Откатить один файл:**
```powershell
git checkout -- src/app/page.tsx
```

**Посмотреть историю:**
```powershell
git log --oneline -15
```
Покажет список вида `8e6576c Sync lockfile`. Левая колонка — хеш.

**Откатиться на конкретный коммит** (все правки после него потеряются):
```powershell
git reset --hard 8e6576c
npm run dev                    # проверить, что работает
git push --force-with-lease origin main    # перезаписать GitHub
```
Render передеплоит откаченную версию.

**Посмотреть, что изменилось в файле:**
```powershell
git diff src/app/page.tsx
```

### 6.5 Безопасный pull (скачать с GitHub)

Нужно только если работали с другого компьютера или кто-то ещё менял репозиторий. **Никогда не делайте `git pull` вслепую** — именно так в проект однажды приехала сломанная версия.

```powershell
git fetch
git log --oneline main..origin/main              # какие коммиты прилетят
git show --stat origin/main | Select -First 40   # какие файлы изменятся
```
Если в списке файлов есть `package.json`, `vite.config.ts`, `index.html`, `src/App.tsx`, `src/main.tsx` — **стоп, не тянуть**. Иначе:
```powershell
git pull
```

### 6.6 Ветки

Рабочая ветка — **`main`**. Только с ней и работаем.
Ветка `vite-rewrite` — архив ошибочной переделки. Удалить (когда захочется):
```powershell
git push origin --delete vite-rewrite
git branch -D vite-rewrite
```

### 6.7 Что git НЕ хранит

Файлы из `.gitignore` не попадают в репозиторий: `node_modules`, `.next`, `.env`, `*.mp4`, `SNAP_*.md`, `Instruction.md`. Это значит: если клонировать репо на другой компьютер, их там не будет — раздел 14.

## 7. Работа с ИИ (нейросетью)

### 7.1 Главное, что нужно понимать

- ИИ **не помнит** предыдущие чаты. Каждый новый чат — с нуля.
- ИИ **не видит** ваши файлы и не может их менять. Он видит только то, что вы вставили в чат, и отдаёт код текстом.
- ИИ без контекста склонен «пересоздать проект заново» — так однажды сайт чуть не переписали на другой движок. Защита от этого — файлы `Instruction.md` и `SNAP_*.md`.

### 7.2 Начало нового чата — пошагово

**Подготовка (в терминале):**
```powershell
cd "D:\Sandalis Web\SIND-site"
git status                                   # должно быть чисто
Get-Content SNAP_1_core.md -TotalCount 1     # хеш в первой строке
git log --oneline -1                         # должен совпадать
```
Если хеши не совпадают — `npm run snapshot`.

**В чате — 6 сообщений подряд:**

| № | Открыть файл, скопировать всё, вставить | Подпись под вставкой |
|---|---|---|
| 1 | `Instruction.md` | «Это правила проекта. Прочитай. Пока не отвечай, жди код.» |
| 2 | `SNAP_1_core.md` | «Снимок кода, часть 1 из 4. Пока не отвечай.» |
| 3 | `SNAP_2_app.md` | «Часть 2 из 4. Пока не отвечай.» |
| 4 | `SNAP_3_shell.md` | «Часть 3 из 4. Пока не отвечай.» |
| 5 | `SNAP_4_workspaces.md` | «Часть 4 из 4. Пока не отвечай.» |
| 6 | — | «Это всё. Задача: …» |

Файлы открывать Блокнотом или VS Code, `Ctrl+A`, `Ctrl+C`.

Если ИИ попросит показать `factory-data.ts`, `item-catalog.ts`, `itemCodes.ts` или `globals.css` целиком — в снимках они обрезаны (большие). Откройте файл из `src/lib/` или `src/app/` и вставьте отдельно.

### 7.3 Как применять код от ИИ

```
1. git status                        → чисто
2. ИИ указал путь файла              → открыть этот файл, заменить содержимое (или вставить кусок, как указано)
3. npm run dev                       → проверить в браузере
4a. Работает   → git add -A ; git commit -m "..." ; git push
4b. Сломалось  → git checkout .      → написать ИИ: «ошибка: <текст из терминала/браузера>»
```

Просите ИИ давать **файл целиком** и **полный путь** — так меньше ошибок при вставке. Если ИИ меняет больше 3–4 файлов за раз — попросите разбить на шаги.

### 7.4 Красные флаги — когда остановиться и переспросить

ИИ предлагает:
- перейти на Vite / создать `vite.config.ts` / `index.html` / `src/App.tsx` / `src/main.tsx`
- «создать `package.json`» или переписать его целиком
- `npm install` для «восстановления проекта»
- «начнём с чистого проекта»
- удалить `src/app` или `src/components`

Ответ ИИ в таких случаях: **«Нет. Проект уже существует на Next.js 16, читай Instruction.md. Работаем внутри существующей структуры.»** Если ИИ упорствует — новый чат.

### 7.5 Когда чат «поплыл»

Признаки: забывает структуру, предлагает файлы, которых нет, повторяет ошибки, отвечает всё медленнее. Не спорьте — откройте новый чат по 7.2. Снимки актуальны на последний коммит, так что ничего не потеряется.

### 7.6 Снимки обновляются сами

После каждого `git commit` срабатывает хук, который пересобирает `SNAP_*.md`. Проверить:
```powershell
Get-Item SNAP_*.md | Select Name, LastWriteTime
```
Время должно совпадать с последним коммитом. Если нет — раздел 12.7.

Вручную: `npm run snapshot`.

## 9. База данных Supabase

### 9.1 Адреса

- **Панель:** https://supabase.com/dashboard → проект (ref `imoeicmsrtvsigjglqqy`)
- **Строка подключения:** Project Settings → Database → Connection string → вкладка **Transaction pooler** (порт 6543)

Таблицы описаны в `src/db/schema.ts`. Это заказы, склады (stockpiles), профили и т.д. — всё, что пользователи создают на сайте. Картинки и код там **не** хранятся.

Локальный сайт (localhost) и Render используют **одну и ту же** базу. Тестовые заказы, созданные локально, будут видны всем. Если нужна отдельная тестовая база — попросите ИИ помочь создать второй проект Supabase и второй `DATABASE_URL` в `.env`.

### 9.4 Изменение структуры базы

Когда ИИ меняет `src/db/schema.ts` (добавляет таблицу или столбец), это надо применить к базе:
```powershell
npx drizzle-kit push
```
Команда покажет, что собирается сделать, и спросит подтверждение. Делать **до** пуша на GitHub, иначе Render запустит новый код на старой базе и страницы упадут.

Графический интерфейс базы прямо с компьютера:
```powershell
npx drizzle-kit studio
```
Откроется в браузере.

### 9.5 Бесплатный тариф Supabase

| Особенность | Что делать |
|---|---|
| **Проект ставится на паузу** после 7 дней без запросов | Заходить на сайт раз в неделю, либо пинг с cron-job.org (раздел 8.3) — он ходит через `/api/health`. Если поставили на паузу — в панели кнопка **Restore project**, 1–2 минуты. |

## 10. Видео и большие файлы

### 10.1 Ограничения

- GitHub: **100 МБ на файл** — иначе `git push` отклоняется.
- Supabase Storage (Free): **50 МБ на файл**.
- Render Free: раздача тяжёлых файлов съедает трафик и тормозит.
- Фоновое видео на главной — исходник `public/Videos/Video Project.mp4`, **225 МБ**. В git его нет (`*.mp4` в `.gitignore`), поэтому на Render его нет.

### 10.2 Текущее состояние

Главная страница (`src/app/page.tsx`) берёт видео из переменной `NEXT_PUBLIC_VIDEO_URL`, а если её нет — из `/Videos/Video Project.mp4` (работает только локально).

_(Впишите сюда, что выбрали, когда решите: «видео лежит на Backblaze B2 по адресу …» или «сжато до … МБ и лежит в Supabase Storage bucket `media`».)_

### 10.3 Вариант без сжатия — Backblaze B2 (бесплатно 10 ГБ)

1. https://www.backblaze.com → B2 Cloud Storage → регистрация.
2. Buckets → Create → **Public** → создать.
3. Upload → загрузить файл, переименованный в `video.mp4` (без пробелов).
4. Кликнуть файл → скопировать **Friendly URL**.
5. Вписать URL в `.env` как `NEXT_PUBLIC_VIDEO_URL=...` и в Render → Environment.
6. `git push` (или Manual Deploy).

### 10.4 Вариант со сжатием — Supabase Storage

Сжать (визуально без потерь; `ffmpeg` уже есть в проекте):
```powershell
cd "D:\Sandalis Web\SIND-site"
& "node_modules\ffmpeg-static\ffmpeg.exe" -i "public\Videos\Video Project.mp4" -c:v libx264 -crf 18 -preset slow -an -movflags +faststart "public\Videos\video.mp4"
[math]::Round((Get-Item "public\Videos\video.mp4").Length / 1MB)
```
Если больше 45 МБ — заменить `-crf 18` на `-crf 22`. Затем: Supabase → Storage → New bucket `media` (**Public**) → Upload → Copy URL → в `.env` и Render как в 10.3.

### 10.5 Другие большие файлы

Любой файл больше ~10 МБ: не в git, а во внешнее хранилище + ссылка. Если случайно закоммитили и `git push` ругается `larger than 100 MB`:
```powershell
git rm --cached "путь/к/файлу"
Add-Content .gitignore "`nпуть/к/файлу"
git commit --amend --no-edit
git push
```

## 11. Секреты, пароли и файл .env

### 11.1 Что где

Файл **`.env`** в корне проекта — только на вашем компьютере, в git не попадает. Содержит:
```
DATABASE_URL="postgresql://postgres.<ref>:<пароль>@aws-1-eu-west-1.pooler.supabase.com:6543/postgres?pgbouncer=true"
ACCESS_TOKEN="<пароль входа на сайт>"
NEXT_PUBLIC_VIDEO_URL=<ссылка на видео>
```
Те же значения лежат в **Render → сервис → Environment** (без кавычек).

Файл **`.env.example`** — шаблон без секретов, он в git. Если добавляете новую переменную в `.env` — добавьте её и в `.env.example` с заглушкой.

### 11.2 Правила

- **Никогда** не вставляйте `.env` целиком в чат с ИИ. Показывайте с заменой значений на `***`:
  ```powershell
  (Get-Content .env) -replace '=.*', '=***'
  ```
- **Никогда** не коммитьте `.env`. Проверка: `git ls-files .env` должно быть пусто.
- Если секрет засветился (в чате, скриншоте, где угодно) — **сменить**:
  - Пароль базы: Supabase → Project Settings → Database → Reset database password. Новый пароль — только латинские буквы и цифры, 20+ символов (спецсимволы вроде `!@#%` ломают строку подключения). Обновить `DATABASE_URL` в `.env` и в Render.
  - `ACCESS_TOKEN`: придумать длинный, обновить в `.env` и в Render. Сообщить клану.
- `ACCESS_TOKEN` вида `0000` подбирается за секунду. Ставьте нормальный.

### 11.3 Где взять DATABASE_URL заново

Supabase → Project Settings → Database → **Connection string** → вкладка **Transaction pooler** → скопировать → заменить `[YOUR-PASSWORD]` на реальный пароль → в конец добавить `?pgbouncer=true`.

## 12. Что-то сломалось — диагностика по симптомам

### 12.1 `npm run dev` пишет `vite` или `"vite" не является командой`

Подменён `package.json`. **Не запускайте `npm install`.**
```powershell
Select-String package.json -Pattern '"next"'      # пусто = подменён
git checkout -- package.json package-lock.json tsconfig.json
Select-String package.json -Pattern '"next"'      # должно найти "next": "16.2.6"
npm run dev
```
Если и после этого пусто — в git тоже сломано: `git log --oneline -- package.json`, найти коммит до поломки, `git checkout <хеш> -- package.json package-lock.json tsconfig.json`.

### 12.2 `Cannot find module` / нет папки `node_modules` / Next не найден

Сначала убедиться, что `package.json` правильный (12.1). Затем:
```powershell
Remove-Item -Recurse -Force node_modules -ErrorAction SilentlyContinue
npm ci
npm run dev
```
`npm ci` ставит точно по `package-lock.json`, 1–2 минуты.

### 12.3 Сайт запускается, но страницы «Заказы»/«Таймеры»/«Кабинет» падают

Проблема с базой. Смотрите в терминале строки `[DB_POOL_ERROR]`, `ECONNREFUSED`, `password authentication failed`, `Tenant or user not found`.
- Проверьте интернет.
- Проверьте, не на паузе ли проект Supabase (панель → Restore).
- Проверьте `DATABASE_URL` в `.env` (раздел 11.3). Если недавно меняли пароль базы — обновили ли строку.
- `DATABASE_URL still contains a placeholder` — в строке остались `<project-ref>` или `<password>`, заменить на реальные.

### 12.4 Локально работает, на Render — нет

Панель Render → сервис → **Logs**. Ищите первую строку с `Error`. Частые:
- `npm ci can only install packages when your package.json and package-lock.json are in sync` → на компьютере: `npm install`, затем `git add package-lock.json; git commit -m "Sync lockfile"; git push`.
- `Cannot find module '@tailwindcss/postcss'` → в `render.yaml` команда сборки должна быть `npm ci --include=dev && npm run build`.
- `DATABASE_URL is required` → переменная не задана в Render → Environment.
- Сборка прошла, но `health check failed` → `/api/health` не отвечает, обычно база (12.3), смотрите логи после `Ready`.

Скопируйте 30–40 строк лога вокруг ошибки — и ИИ.

### 12.5 На Render `JavaScript heap out of memory`

Не хватает 512 МБ на сборку. Render → Environment → добавить `NODE_OPTIONS` = `--max-old-space-size=460` → Save → Manual Deploy. Не помогло → тариф Starter.

### 12.6 Сайт в интернете открывается 40 секунд

Норма для бесплатного Render после 15 минут простоя. Решение — пинг (8.3) или платный тариф.

### 12.7 Снимки SNAP_* не обновляются после коммита

```powershell
Test-Path .git\hooks\post-commit
```
`False` → создать хук:
```powershell
$hook = "#!/bin/sh`npowershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/snapshot.ps1 >/dev/null 2>&1`nexit 0`n"
[IO.File]::WriteAllText("$PWD\.git\hooks\post-commit", $hook)
```
`True`, но не работает → запустить скрипт руками и посмотреть ошибку:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/snapshot.ps1
```
Ошибка с кракозябрами → файл потерял кодировку BOM:
```powershell
$c = Get-Content scripts\snapshot.ps1 -Raw -Encoding UTF8
[IO.File]::WriteAllText("$PWD\scripts\snapshot.ps1", $c, (New-Object System.Text.UTF8Encoding $true))
```

### 12.8 `git push` отклонён: `rejected`, `non-fast-forward`

На GitHub есть коммиты, которых нет у вас. Сначала посмотреть, что там (6.5). Если это ваш же старый мусор и вы уверены — `git push --force-with-lease origin main`.

### 12.9 `git push` отклонён: `file is larger than 100 MB`

Раздел 10.5.

### 12.10 После логина сразу выкидывает / не держит сессию (на Render)

Проблема с cookie под HTTPS. Показать ИИ файлы `src/app/api/auth/login/route.ts` и `src/proxy.ts`.

### 12.11 Не помню, что сломал, всё странно

```powershell
git status          # что изменено
git diff            # что именно
git checkout .      # откатить всё
npm run dev
```
Если и после отката плохо — `git log --oneline -10`, взять хеш последнего заведомо рабочего коммита, `git reset --hard <хеш>`. Совсем плохо — раздел 13.

## 2. Что это вообще такое (карта проекта)

**SIND-site** — сайт клана для игры Foxhole: заказы на производство, склады, таймеры, база кодов предметов, карта, тренировки.

Проект состоит из трёх частей, которые живут в разных местах:

```
┌─────────────────────────────┐
│  ВАШ КОМПЬЮТЕР              │   D:\Sandalis Web\SIND-site
│  Здесь вы редактируете код  │   Запуск: npm run dev → localhost:3000
└──────────────┬──────────────┘
               │ git push
               ▼
┌─────────────────────────────┐
│  GITHUB                     │   github.com/Reppot/Sandalis-Web
│  Хранилище кода и история   │   Каждый коммит = точка восстановления
└──────────────┬──────────────┘
               │ автоматически при каждом push
               ▼
┌─────────────────────────────┐        ┌────────────────────────────┐
│  RENDER (хостинг)           │ ─────► │  SUPABASE (база данных)    │
│  Сайт в интернете           │        │  Заказы, склады, таймеры   │
│  sandalis-web-mtbf          │        │  PostgreSQL                │
│  .onrender.com              │        │                            │
└─────────────────────────────┘        └────────────────────────────┘
```

**Как это работает вместе:**
- Вы меняете код на компьютере → проверяете локально → отправляете на GitHub (`git push`).
- Render видит новый код на GitHub и **сам** пересобирает и перезапускает сайт (3–5 минут).
- И локальный сайт, и сайт на Render ходят в **одну и ту же** базу Supabase. То есть заказ, созданный на localhost, появится и на «боевом» сайте.

**Технологии** (знать названия достаточно, чтобы говорить с ИИ):
- **Next.js 16** — фреймворк сайта (движок). Версия 16.2.6.
- **React 19** — библиотека интерфейса.
- **TypeScript** — язык (JavaScript с типами).
- **Tailwind CSS 4** — стили.
- **Drizzle ORM** — прослойка между кодом и базой данных.
- **PostgreSQL** — сама база данных (у Supabase).

**Файлы в папке проекта — что зачем:**

|---|---|---|

## 3. Словарь терминов

| Термин | Простыми словами |
|---|---|
| **Терминал / PowerShell** | Чёрное окно, куда пишут команды текстом. |
| **Команда** | Строка текста, которую вы вводите в терминал и нажимаете Enter. |
| **Git** | Программа-«машина времени» для кода. Запоминает каждое сохранение, позволяет откатиться. |
| **Коммит (commit)** | Одно «сохранение» в git с подписью, что сделано. Точка, к которой можно вернуться. |
| **Пуш (push)** | Отправить коммиты с компьютера на GitHub. |
| **Пул (pull)** | Скачать коммиты с GitHub на компьютер. Опасная операция, см. 6.5. |
| **Репозиторий (репо)** | Папка проекта под управлением git + её копия на GitHub. |
| **Ветка (branch)** | Параллельная версия кода. У нас рабочая — `main`. Ветка `vite-rewrite` — мусор. |
| **Хеш коммита** | Код вида `d2e8b7d` — «номер» сохранения. |
| **npm** | Менеджер библиотек. `npm run dev` — запустить сайт, `npm install` — установить библиотеки. |
| **node_modules** | Папка, куда npm складывает библиотеки. Её можно удалить и восстановить командой `npm install` — **но только если `package.json` правильный**. |
| **Сборка (build)** | Превращение исходного кода в готовый сайт. Делает `npm run build` и Render. |
| **Деплой (deploy)** | Выкладка новой версии сайта на хостинг. Render делает сам после `git push`. |
| **Хостинг** | Сервер в интернете, где крутится сайт. У нас Render. |
| **База данных (БД)** | Место, где хранятся заказы, склады и т.д. У нас Supabase (PostgreSQL). |
| **Переменные окружения (env)** | Настройки-секреты, которые не пишут в код: пароль базы, пароль сайта. Лежат в `.env` локально и в панели Render. |
| **DATABASE_URL** | Строка подключения к базе — адрес + логин + пароль в одной строке. |
| **ACCESS_TOKEN** | Пароль для входа на сайт (клановый). |
| **localhost:3000** | Адрес сайта, запущенного на вашем компьютере. Виден только вам. |
| **Снимок (SNAP)** | Файлы `SNAP_1…4.md` — весь код проекта, собранный в текст, чтобы вставить ИИ в чат. |

## 6. Git — сохранение и откат изменений

### 6.1 Золотое правило

> **Перед любыми правками — `git status` должен быть чистым.**
> **После каждого рабочего результата — коммит и пуш.**

Тогда любая неудачная правка откатывается за секунду, а не восстановлением из бэкапа.

### 6.2 Посмотреть состояние

```powershell
git status
```
- `nothing to commit, working tree clean` — всё сохранено, можно работать.
- `modified: ...` — файлы изменены, но не сохранены в git.
- `Untitled files: ...` / `Untracked files:` — новые файлы, git о них ещё не знает.
- `Your branch is behind 'origin/main'` — на GitHub есть коммиты, которых нет у вас. **Не спешите делать pull**, см. 6.5.

### 6.3 Сохранить изменения (коммит + пуш)

```powershell
git add -A
git commit -m "Что сделано, коротко по-русски"
git push
```
Пример подписи: `"Добавлен фильтр на страницу заказов"`.
После `git push` Render автоматически начнёт пересборку сайта (раздел 8).

### 6.4 Откатить изменения

**Откатить всё незакоммиченное** (вернуться к последнему коммиту):
```powershell
git checkout .
```

**Откатить один файл:**
```powershell
git checkout -- src/app/page.tsx
```

**Посмотреть историю:**
```powershell
git log --oneline -15
```
Покажет список вида `8e6576c Sync lockfile`. Левая колонка — хеш.

**Откатиться на конкретный коммит** (все правки после него потеряются):
```powershell
git reset --hard 8e6576c
npm run dev                    # проверить, что работает
git push --force-with-lease origin main    # перезаписать GitHub
```
Render передеплоит откаченную версию.

**Посмотреть, что изменилось в файле:**
```powershell
git diff src/app/page.tsx
```

### 6.5 Безопасный pull (скачать с GitHub)

Нужно только если работали с другого компьютера или кто-то ещё менял репозиторий. **Никогда не делайте `git pull` вслепую** — именно так в проект однажды приехала сломанная версия.

```powershell
git fetch
git log --oneline main..origin/main              # какие коммиты прилетят
git show --stat origin/main | Select -First 40   # какие файлы изменятся
```
Если в списке файлов есть `package.json`, `vite.config.ts`, `index.html`, `src/App.tsx`, `src/main.tsx` — **стоп, не тянуть**. Иначе:
```powershell
git pull
```

### 6.6 Ветки

Рабочая ветка — **`main`**. Только с ней и работаем.
Ветка `vite-rewrite` — архив ошибочной переделки. Удалить (когда захочется):
```powershell
git push origin --delete vite-rewrite
git branch -D vite-rewrite
```

### 6.7 Что git НЕ хранит

Файлы из `.gitignore` не попадают в репозиторий: `node_modules`, `.next`, `.env`, `*.mp4`, `SNAP_*.md`, `Instruction.md`. Это значит: если клонировать репо на другой компьютер, их там не будет — раздел 14.

## 7. Работа с ИИ (нейросетью)

### 7.1 Главное, что нужно понимать

- ИИ **не помнит** предыдущие чаты. Каждый новый чат — с нуля.
- ИИ **не видит** ваши файлы и не может их менять. Он видит только то, что вы вставили в чат, и отдаёт код текстом.
- ИИ без контекста склонен «пересоздать проект заново» — так однажды сайт чуть не переписали на другой движок. Защита от этого — файлы `Instruction.md` и `SNAP_*.md`.

### 7.2 Начало нового чата — пошагово

**Подготовка (в терминале):**
```powershell
cd "D:\Sandalis Web\SIND-site"
git status                                   # должно быть чисто
Get-Content SNAP_1_core.md -TotalCount 1     # хеш в первой строке
git log --oneline -1                         # должен совпадать
```
Если хеши не совпадают — `npm run snapshot`.

**В чате — 6 сообщений подряд:**

| № | Открыть файл, скопировать всё, вставить | Подпись под вставкой |
|---|---|---|
| 1 | `Instruction.md` | «Это правила проекта. Прочитай. Пока не отвечай, жди код.» |
| 2 | `SNAP_1_core.md` | «Снимок кода, часть 1 из 4. Пока не отвечай.» |
| 3 | `SNAP_2_app.md` | «Часть 2 из 4. Пока не отвечай.» |
| 4 | `SNAP_3_shell.md` | «Часть 3 из 4. Пока не отвечай.» |
| 5 | `SNAP_4_workspaces.md` | «Часть 4 из 4. Пока не отвечай.» |

Файлы открывать Блокнотом или VS Code, `Ctrl+A`, `Ctrl+C`.

### 7.3 Как применять код от ИИ

```

4a. Работает   → git add -A ; git commit -m "..." ; git push
4b. Сломалось  → git checkout .      → написать ИИ: «ошибка: <текст из терминала/браузера>»
```

Просите ИИ давать **файл целиком** и **полный путь** — так меньше ошибок при вставке. Если ИИ меняет больше 3–4 файлов за раз — попросите разбить на шаги.

### 7.4 Красные флаги — когда остановиться и переспросить

ИИ предлагает:
- перейти на Vite / создать `vite.config.ts` / `index.html` / `src/App.tsx` / `src/main.tsx`
- «создать `package.json`» или переписать его целиком
- `npm install` для «восстановления проекта»
- «начнём с чистого проекта»
- удалить `src/app` или `src/components`

Ответ ИИ в таких случаях: **«Нет. Проект уже существует на Next.js 16, читай Instruction.md. Работаем внутри существующей структуры.»** Если ИИ упорствует — новый чат.

### 7.5 Когда чат «поплыл»

Признаки: забывает структуру, предлагает файлы, которых нет, повторяет ошибки, отвечает всё медленнее. Не спорьте — откройте новый чат по 7.2. Снимки актуальны на последний коммит, так что ничего не потеряется.

### 7.6 Снимки обновляются сами

После каждого `git commit` срабатывает хук, который пересобирает `SNAP_*.md`. Проверить:
```powershell
Get-Item SNAP_*.md | Select Name, LastWriteTime
```
Время должно совпадать с последним коммитом. Если нет — раздел 12.7.

Вручную: `npm run snapshot`.

Команда покажет, что собирается сделать, и спросит подтверждение. Делать **до** пуша на GitHub, иначе Render запустит новый код на старой базе и страницы упадут.

Графический интерфейс базы прямо с компьютера:
```powershell

## 10. Видео и большие файлы

### 10.1 Ограничения

- GitHub: **100 МБ на файл** — иначе `git push` отклоняется.
- Supabase Storage (Free): **50 МБ на файл**.
- Render Free: раздача тяжёлых файлов съедает трафик и тормозит.
- Фоновое видео на главной — исходник `public/Videos/Video Project.mp4`, **225 МБ**. В git его нет (`*.mp4` в `.gitignore`), поэтому на Render его нет.

### 10.2 Текущее состояние

Главная страница (`src/app/page.tsx`) берёт видео из переменной `NEXT_PUBLIC_VIDEO_URL`, а если её нет — из `/Videos/Video Project.mp4` (работает только локально).

_(Впишите сюда, что выбрали, когда решите: «видео лежит на Backblaze B2 по адресу …» или «сжато до … МБ и лежит в Supabase Storage bucket `media`».)_

### 10.3 Вариант без сжатия — Backblaze B2 (бесплатно 10 ГБ)

1. https://www.backblaze.com → B2 Cloud Storage → регистрация.
2. Buckets → Create → **Public** → создать.
3. Upload → загрузить файл, переименованный в `video.mp4` (без пробелов).
4. Кликнуть файл → скопировать **Friendly URL**.
5. Вписать URL в `.env` как `NEXT_PUBLIC_VIDEO_URL=...` и в Render → Environment.
6. `git push` (или Manual Deploy).

### 10.4 Вариант со сжатием — Supabase Storage

Сжать (визуально без потерь; `ffmpeg` уже есть в проекте):

cd "D:\Sandalis Web\SIND-site"
& "node_modules\ffmpeg-static\ffmpeg.exe" -i "public\Videos\Video Project.mp4" -c:v libx264 -crf 18 -preset slow -an -movflags +faststart "public\Videos\video.mp4"

```
Если больше 45 МБ — заменить `-crf 18` на `-crf 22`. Затем: Supabase → Storage → New bucket `media` (**Public**) → Upload → Copy URL → в `.env` и Render как в 10.3.

### 10.5 Другие большие файлы

Любой файл больше ~10 МБ: не в git, а во внешнее хранилище + ссылка. Если случайно закоммитили и `git push` ругается `larger than 100 MB`:

Add-Content .gitignore "`nпуть/к/файлу"

git push

## 11. Секреты, пароли и файл .env

### 11.1 Что где

Файл **`.env`** в корне проекта — только на вашем компьютере, в git не попадает. Содержит:
```
DATABASE_URL="postgresql://postgres.<ref>:<пароль>@aws-1-eu-west-1.pooler.supabase.com:6543/postgres?pgbouncer=true"
ACCESS_TOKEN="<пароль входа на сайт>"

```
Те же значения лежат в **Render → сервис → Environment** (без кавычек).

Файл **`.env.example`** — шаблон без секретов, он в git. Если добавляете новую переменную в `.env` — добавьте её и в `.env.example` с заглушкой.

### 11.2 Правила

- **Никогда** не вставляйте `.env` целиком в чат с ИИ. Показывайте с заменой значений на `***`:
  ```powershell
  (Get-Content .env) -replace '=.*', '=***'
  ```
- **Никогда** не коммитьте `.env`. Проверка: `git ls-files .env` должно быть пусто.
- Если секрет засветился (в чате, скриншоте, где угодно) — **сменить**:
  - Пароль базы: Supabase → Project Settings → Database → Reset database password. Новый пароль — только латинские буквы и цифры, 20+ символов (спецсимволы вроде `!@#%` ломают строку подключения). Обновить `DATABASE_URL` в `.env` и в Render.
  - `ACCESS_TOKEN`: придумать длинный, обновить в `.env` и в Render. Сообщить клану.
- `ACCESS_TOKEN` вида `0000` подбирается за секунду. Ставьте нормальный.

### 11.3 Где взять DATABASE_URL заново

Supabase → Project Settings → Database → **Connection string** → вкладка **Transaction pooler** → скопировать → заменить `[YOUR-PASSWORD]` на реальный пароль → в конец добавить `?pgbouncer=true`.

## 12. Что-то сломалось — диагностика по симптомам

### 12.1 `npm run dev` пишет `vite` или `"vite" не является командой`

Подменён `package.json`. **Не запускайте `npm install`.**
```powershell
Select-String package.json -Pattern '"next"'      # пусто = подменён
git checkout -- package.json package-lock.json tsconfig.json
Select-String package.json -Pattern '"next"'      # должно найти "next": "16.2.6"
npm run dev
```
Если и после этого пусто — в git тоже сломано: `git log --oneline -- package.json`, найти коммит до поломки, `git checkout <хеш> -- package.json package-lock.json tsconfig.json`.

### 12.2 `Cannot find module` / нет папки `node_modules` / Next не найден

Сначала убедиться, что `package.json` правильный (12.1). Затем:
```powershell
Remove-Item -Recurse -Force node_modules -ErrorAction SilentlyContinue
npm ci
npm run dev
```
`npm ci` ставит точно по `package-lock.json`, 1–2 минуты.

### 12.3 Сайт запускается, но страницы «Заказы»/«Таймеры»/«Кабинет» падают

Проблема с базой. Смотрите в терминале строки `[DB_POOL_ERROR]`, `ECONNREFUSED`, `password authentication failed`, `Tenant or user not found`.
- Проверьте интернет.
- Проверьте, не на паузе ли проект Supabase (панель → Restore).
- Проверьте `DATABASE_URL` в `.env` (раздел 11.3). Если недавно меняли пароль базы — обновили ли строку.
- `DATABASE_URL still contains a placeholder` — в строке остались `<project-ref>` или `<password>`, заменить на реальные.

### 12.4 Локально работает, на Render — нет

Панель Render → сервис → **Logs**. Ищите первую строку с `Error`. Частые:
- `npm ci can only install packages when your package.json and package-lock.json are in sync` → на компьютере: `npm install`, затем `git add package-lock.json; git commit -m "Sync lockfile"; git push`.
- `Cannot find module '@tailwindcss/postcss'` → в `render.yaml` команда сборки должна быть `npm ci --include=dev && npm run build`.
- `DATABASE_URL is required` → переменная не задана в Render → Environment.
- Сборка прошла, но `health check failed` → `/api/health` не отвечает, обычно база (12.3), смотрите логи после `Ready`.

Скопируйте 30–40 строк лога вокруг ошибки — и ИИ.

### 12.5 На Render `JavaScript heap out of memory`

Не хватает 512 МБ на сборку. Render → Environment → добавить `NODE_OPTIONS` = `--max-old-space-size=460` → Save → Manual Deploy. Не помогло → тариф Starter.

### 12.6 Сайт в интернете открывается 40 секунд

Норма для бесплатного Render после 15 минут простоя. Решение — пинг (8.3) или платный тариф.

### 12.7 Снимки SNAP_* не обновляются после коммита

```powershell
Test-Path .git\hooks\post-commit
```
`False` → создать хук:
```powershell
$hook = "#!/bin/sh`npowershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/snapshot.ps1 >/dev/null 2>&1`nexit 0`n"
[IO.File]::WriteAllText("$PWD\.git\hooks\post-commit", $hook)
```
`True`, но не работает → запустить скрипт руками и посмотреть ошибку:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/snapshot.ps1
```
Ошибка с кракозябрами → файл потерял кодировку BOM:
```powershell
$c = Get-Content scripts\snapshot.ps1 -Raw -Encoding UTF8
[IO.File]::WriteAllText("$PWD\scripts\snapshot.ps1", $c, (New-Object System.Text.UTF8Encoding $true))
```

### 12.8 `git push` отклонён: `rejected`, `non-fast-forward`

На GitHub есть коммиты, которых нет у вас. Сначала посмотреть, что там (6.5). Если это ваш же старый мусор и вы уверены — `git push --force-with-lease origin main`.

### 12.9 `git push` отклонён: `file is larger than 100 MB`

Раздел 10.5.

### 12.10 После логина сразу выкидывает / не держит сессию (на Render)

Проблема с cookie под HTTPS. Показать ИИ файлы `src/app/api/auth/login/route.ts` и `src/proxy.ts`.

### 12.11 Не помню, что сломал, всё странно

```powershell
git status          # что изменено
git diff            # что именно
git checkout .      # откатить всё
npm run dev
```
Если и после отката плохо — `git log --oneline -10`, взять хеш последнего заведомо рабочего коммита, `git reset --hard <хеш>`. Совсем плохо — раздел 13.

## 16. Чего никогда не делать

1. **`npm install`, когда `npm run dev` показывает vite** — снесёт правильные библиотеки. Сначала 12.1.
2. **`npm audit fix --force`** — поднимет версии и сломает проект.
3. **`git pull` без `git fetch` и просмотра** — так приезжает чужой мусор.
4. **Распаковывать архивы / копировать чужие проекты в папку `SIND-site`** — так подменился `package.json`.
5. **Править `package-lock.json` руками.**
6. **Коммитить `.env`** или вставлять его в чат с секретами.
7. **Удалять или изменять `D:\Sandalis Web\BackUps\39`.**
8. **Соглашаться с ИИ на «пересоздать проект», «перейти на Vite», «создать index.html».**
9. **Менять `DATABASE_URL` на порт 5432 (Direct connection)** — Render не подключится.
10. **Работать без `git commit` больше часа** — потеря будет болезненной.
